## Design specificity verdict
The native look is right for a Mac utility. The core idea (hard presses sound harder) appears only in the Response curve dot and in Diagnostics. The panel could belong to any audio app. The Cherry MX stem-colour vocabulary goes unused. The icon's gold sparkle reads as "AI feature". At menu-bar size the cross stem reads as a "+" or medical cross. Detector: 0 findings, not applicable: folder scans skip .swift, and the rules target CSS/HTML.

## What's working
1. Live Response curve with calibration anchors and a last-press dot (TypingForceSettingsView.swift:47-50).
2. Honest privacy and side-effect copy (Exclusions footer, export note, inline sensor fallback).
3. Native restraint, state-aware menu-bar icon, solid realtime engineering.

## Priority issues
1. [P1] Onboarding hides the payoff: 8 steps, 3 just show results, first sound at step 6, ends on mg values. Fix: Welcome, Input Monitoring, Hear it, optional Calibrate, Done; run the checks silently. /impeccable onboard
2. [P1] Return can abort calibration: the footer Skip is the default action while the practice field has focus (OnboardingView.swift:58-59). Cancel moves onboarding forward (CalibrationView.swift:160-163). Closing onboarding never marks it done (AppModel.swift:69). /impeccable harden
3. [P1] Status by colour only: an unlabelled status dot (MenuBarView.swift:14-17). Light-mode contrast: Allowed 2.07:1, orange warnings ~2.2:1, Soft/Aggressive labels 1.82:1. The menu-bar icon's VoiceOver label has no state. /impeccable harden + colorize
4. [P2] Engineering terms leak into the UI: raw SensorState codes in 7 places, Simulated mode in the panel, repo doc paths, five names for one idea. /impeccable clarify + distill
5. [P2] Not fully Mac-standard: segmented Settings tabs, no ⌘, / ⌘Q, panel rows with no hover highlight, Sound pane pushes playback about 800pt down. /impeccable layout + harden
